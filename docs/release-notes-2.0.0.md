# 2.0.0 正式版说明 · 收官版本

> 装包后请**强刷浏览器（Ctrl+Shift+R）**，并**完整重启一次 Halo 服务**（仅替换 jar 不重启，Halo 会继续用内存里的旧代码）。

这是**最后一个功能版本**。此后本插件不再新增功能，只维持可用。所以这一版的重点不是"还能做什么"，而是**让它在你不管它的情况下也不容易坏、坏了你能自己看出来**。

## 一、插件内自检：提醒不弹时，先点这里

设置里新增「**提醒自检**」卡片，点一下会沿着提醒链路逐项检查，并用人话告诉你结论：

| 检查项 | 它会告诉你 |
| --- | --- |
| 提醒接口 | 能不能取到提醒数据、当前有几条进入提醒期 |
| 服务端版本 | 后端实际在跑的版本（排查"换了包没生效"） |
| 插件版本 | 插件版本与服务端版本是否一致 —— 不一致几乎就是**换了 jar 没重启** |
| 弹窗脚本 | 当前页面有没有注入弹窗脚本、脚本序号是多少 |

任何一项异常都会直接给出下一步该做什么（强刷浏览器 / 重启 Halo / 检查开关）。**这一项是为"以后没人给你排查"准备的**：以前这类问题只能靠翻日志和猜，现在用户自己点一下就有答案。

## 二、使用说明搬进了插件里

从应用市场安装的用户**看不到仓库里的 README**，所以把用法直接放进设置页，做成可折叠的「**使用说明与常见问题**」：

- 三步就能用起来（先记日子 → 想管车再加座驾 → 要公开才开前台开关）
- 提醒会在哪三个地方出现
- 弹窗为什么"刷新又出来了"、怎么才能不烦我
- 默认值是给谁看的（哪些内容默认不对访客展示）
- 到期了没办会怎么样（逾期 → 待处理 → 一直保留，可撤销）
- **提醒没出现怎么办**（三步排查）
- 数据在哪、怎么搬走

## 三、条目多了也能一眼看出最近要办什么

「记得」页的重要日期列表此前只能按人员筛选，排序还是拖拽顺序 —— 条目一多，根本看不出"最近有什么"。

- 新增**临近程度筛选**：全部 / 今天 / 7 天内 / 30 天内 / 30 天以后，每档都带条目数；
- 新增「**还有**」列：直接显示「明天」「5 天后」「已过 3 天」，临近的用颜色标出来。

## 四、修掉一个会打乱顺序的问题

拖拽排序此前把**筛选后可见的那几条**的顺序整份写回，于是**被筛掉的条目顺序被抹平**，会在列表里悄悄跳位。现在只移动可见项，其余条目保持原有相对位置。加了临近程度筛选之后这个问题的破坏力会成倍放大，所以一并修掉。

## 五、弹窗的无障碍与小改进

- **支持 Esc 关闭**：按键盘的习惯动作只收起当前弹窗，**不写任何静音记录**（不该因为按了下 Esc 就"以后都不提醒"）。
- 关闭按钮从 `<span>` 换成真正的 `<button>`：可以 **Tab 聚焦**、回车触发，读屏软件能正确朗读「关闭提醒」。
- 弹窗语义从 `role="alert"` 改为 `role="status" + aria-live="polite"`：这是提醒不是报错，不该打断用户正在听的内容。

## 六、描述收敛成一句话

插件描述从 200 多字的长句改成一句话：

> 把容易忘的事记下来：纪念日与生日、家人朋友、爱车的保险年检保养到期，到点提醒你，愿意公开的还能展示在博客前台。

## 七、关于后续维护

- **升级方式**：请在「插件」页面上传新 jar 升级。**不要手工替换 plugins 目录里的文件** —— Halo 在数据库里记录插件的加载路径，换了文件名它就不再加载（表现为接口 404、后台菜单消失）。
- **数据安全**：纪念日、人员、座驾都存在 Halo 自己的数据里，卸载插件不会替你删除；「记得」页右上角的**导出**可以把全部内容存成 JSON 留底。
- 遇到问题先点「提醒自检」，它能覆盖绝大多数"提醒不出现"的情况。
