# 1.3.1 正式版说明 · 悬浮提醒修好了，并改为每次打开都提示

> 装包后请**强刷浏览器（Ctrl+Shift+R）**，并**完整重启一次 Halo 服务**（仅替换 jar 不重启，Halo 会继续用内存里的旧代码 —— 这一条是本次排查中最容易踩的坑）。

## 一、修掉「悬浮提醒不出现」的一串问题

1.3.0 的悬浮弹窗实际上**弹不出来**，原因不止一个，全在投递链路上：

- **纪念日 / 生日被过滤掉**：弹窗清单用「状态必须为待办」筛选，但只有座驾到期项带这个字段，纪念日/生日没有，于是**全部被丢弃** —— 弹窗对纪念日从来就没生效过；
- **渲染时就记了「已提醒」**：页面渲染阶段先把节点标记成已提醒，脚本随后再去取数据时已被过滤，自然没有内容可弹（1.2.6 时弹窗内容内嵌在页面里，所以当时是对的，1.2.7 改成实时拉取后变成回归）；
- **「已弹过」上报接口对访客是 403**：Halo 默认只放行插件路由的 GET，写操作需要权限配置，因此该接口从未可用；
- **数据与页面作用域不匹配**：一度把弹窗数据放在「记得」页面的数据块里，而「显示范围」设为**全站所有页面**时，其它页面拿不到任何数据 —— 表现为只在某一个页面弹、甚至完全不弹。

现在数据统一由公开的 `GET /important-dates-reminders` 提供，无论显示范围是「仅记得页面」还是「全站所有页面」都能取到。

## 二、行为调整：每次打开页面都提示

按站主要求，弹窗改为**每次打开页面都会出现**（此前是同一浏览器只弹一次）。数据实时拉取，因此后台改了内容，前台下一次打开就是新的。

**关闭方式菜单**（默认开启）不变：点 × 可选 **本次关闭 / 3 天内不显示 / 10 天内不显示 / 永久关闭**，时长与永久记录在访客浏览器，到期自动恢复。

> ⚠️ 菜单有 **5 秒超时**：未选择则执行「× 关闭默认行为」。请把该默认项设为「本次关闭」或「3 天内不显示」，**不要设为「永久关闭」**，否则手慢一点就会被永久静音。

## 三、修掉一个会「静默静音」的坑

菜单关闭时，点 × 原本会**直接套用「× 关闭默认行为」**。若默认值是时长或永久，一次点击就会写入静音记录，而**菜单未显示、没有任何反馈**，用户只看到"刷新一次之后就再也不弹了"。

现在：**菜单关闭时，点 × 只收起当前弹窗**，不写任何静音记录；需要时长/永久选项时把菜单打开即可（那时是明确选择）。

## 四、顺带修掉的一个服务端问题

整理代码时误删了提醒接口的配置字段，导致响应缺少 `enabled` / `remindDays` / `toastEnabled` 等字段。已恢复；同时**接口新增 `build` 字段**，用于确认站点上实际生效的是哪一版服务端逻辑（插件目录里残留多个 jar、或只换 jar 未重启时，插件页显示的版本号并不代表实际运行的代码）。

## 五、验证

在真实 Halo 2.26 实例上：

| 点 × 不再静默静音 | **4/4 PASS** |
| 关闭方式菜单的时长/永久选项仍有效 | **3/3 PASS** |
| 全站作用域（非「记得」页面也弹） | **4/4 PASS** |

| 前台回归 | **5/5 PASS** |

## 六、升级方式

- **Halo 2.26 及以上**；由 1.2.x / 1.3.0 直接升级，**数据不会丢失**，无需迁移脚本；
- **务必完整重启 Halo 服务**，并建议清理 `plugins` 目录下其它 `plugin-important-dates-*.jar`，只保留新版；
- 浏览器**强刷一次**（插件静态资源带一年缓存，脚本已带上新版本参数会自动失效）；
- 若此前点过 × 且默认行为是永久关闭，浏览器里可能留有静音记录，清一次即可恢复：
  `localStorage.removeItem('id-toast-forever'); localStorage.removeItem('id-toast-until');`（控制台执行后刷新）。
